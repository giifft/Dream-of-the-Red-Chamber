# 🧠 项目自进化经验库 (Learnings)

本目录是 **红楼智数专家团 (RedChamber-Swarm)** 实现**自我学习与自我进化**的知识沉淀中心。通过记录项目开发过程中的成功经验与失败教训，使 Agent 团队在后续的开发中能够自动规避历史错误并复用最佳实践。

## 目录结构

- [README.md](./README.md)：本说明文件（随仓库分发）。
- `successful_patterns.md`：沉淀的成功设计模式、高效代码片段、优化的 Prompt 模板以及解决复杂技术栈的方法。**内部文件，不随仓库分发**——clone 后由团队运行时自动生成。
- `bad_cases.md`：沉淀的历史 Bug、幻觉、安全漏洞（如 4A 绕过、注入攻击）及应对防退化测试用例。**内部文件，不随仓库分发**。
- `evolution_log.md`：记录团队进化规约（Evolutionary Protocols）与复盘版本历史。**内部文件，不随仓库分发**。
- `checkpoint.json`：工作流断点续跑状态。**内部文件，不随仓库分发**。

> ⚠️ 以上 `.md` 和 `.json` 文件已通过 `.gitignore` 排除版本控制。它们包含团队内部审计过程、踩坑细节和修复方案，属于开发过程的私有沉淀。首次使用时团队会在第一次任务交付后自动创建这些文件。

## 进化规则与流程

1. **前置检索**：王熙凤 (Team Lead) 在接收到任务并分派给具体角色前，必须优先读取并分析本目录下的经验与 `evolution_log.md` 中的活跃规约，将规约作为硬约束、历史经验作为任务上下文传递给对应成员。
2. **后置总结**：项目交付（QA 验证通过后），王熙凤必须总结本次任务的"成功亮点"、"踩坑记录"与"进化规约"，按规范更新写入 `successful_patterns.md`、`bad_cases.md` 和 `evolution_log.md`。
3. **防退化校验**：紫鹃 (QA) 在执行测试时，必须对照 `bad_cases.md` 中记录的历史缺陷设计防退化（Anti-Regression）测试用例，确保修改后的代码未破坏已有功能的稳定性。
